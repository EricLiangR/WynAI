# UAT-AY 执行计划

## 目标

1. 验证数据集 `01测试销售订单-09`（`18b86197-65e3-4682-8501-6e7125afad02`）的元数据、字段语义和副本身份。
2. 验证源数据集 `a53ec17a-a8e7-43ce-8552-ec4805071efa` 对应的销售商机 Skill 是否适用于目标副本，并记录 Skill 绑定证据。
3. 执行全部 34 条客户问题，覆盖金额、名单、产品、客户类型、项目属性、时间口径、聚合、排序和阈值筛选。
4. 对每条问题保留请求、响应、查询计划、日志 trace 和页面截图，形成可复核证据链。
5. 对边界明确的缺陷实施最小修复并回归；对需要业务口径、架构或产品决策的增强只输出建议。

## 测试边界

- 数据集只读，不修改客户数据、Wyn 数据集或业务语义配置。
- 平台服务使用本轮独立端口和运行数据目录。
- 每条问题使用独立会话；重复问题仍保留独立编号，用于一致性验证。
- `某个客户的商机金额是多少`属于缺少客户实体的歧义问题，预期为受控澄清，不要求平台猜测。
- “今年/去年/财年26/所有财年”的实际口径以数据集字段、Skill 和平台当前日期规则共同核验，不预先假定结果。

## 通过标准

- 数据集 ID、名称和元数据可访问，目标副本不被错误替换为源数据集。
- 适用 Skill 被解析并在请求/响应审计中可追踪。
- 结果字段满足问题要求，过滤条件、时间范围、聚合、排序和阈值逻辑正确。
- 金额、数量和占比能与独立数据核验或平台确定性结果一致。
- 无明显前端溢出、空白结果误导、错误吞没或日志无法关联问题的情况。
- 受控澄清问题明确说明缺少条件，并提供可继续执行的提示。

## 缺陷处置

- P0/P1：阻断核心业务查询或返回错误业务结论，优先修复并全量回归相关用例。
- P2：影响一类或多类查询的正确性、可追溯性或主要展示，修复后做针对性回归。
- P3：展示、措辞、日志字段或体验不足，记录修复或增强建议。
- 涉及财年定义、默认指标、权限、模型策略、数据模型或跨模块协议的事项，不在本轮直接改变业务行为，进入决策清单。
