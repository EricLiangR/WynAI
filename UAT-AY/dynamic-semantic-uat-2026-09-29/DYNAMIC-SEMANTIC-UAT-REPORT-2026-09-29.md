## 3. 重点发现

### 3.1 DYN-10：时间分组修复后按合法空结果完成

修复前曾因 Skill Registry 丢失期间字段绑定、WAX 适配器无条件拒绝带 `grain` 的请求而阻断。修复后页面技术详情确认：返回字段和分组维度均为 `赢单季度`，源端筛选为 `赢单财年 等于 26`，筛选、分组、聚合和排序均由 Wyn 执行，结果范围为 `0 行；完整结果`，替代结果未使用。FY26 无数据时返回明确空结果，不把空结果改写为错误，也不使用 fallback 或平台本地时间归并。

### 3.2 DYN-07/DYN-09：结果粒度修复后与用户要求一致

- 修复前 DYN-07 的摘要与 8,067 条源记录不一致；修复后 Wyn 按客户维度返回 7 个唯一客户。
- 修复前 DYN-09 的返回行缺少可区分商机的业务粒度；修复后 Wyn 按受治理的商机业务键返回 1 条唯一记录。

这两项不是 LLM 调用失败，也不是前端分页故障，而是“用户请求粒度、源端结果粒度、展示投影”之间缺少一致性门禁。本轮通过通用结果契约和 LLM request unit 规划修复，未增加 AY 问题关键词、固定字段或业务 fallback。

### 3.3 服务运行事件

DYN-07 首次提交时浏览器收到 `Failed to fetch`，随后 8787 端口短暂失去响应。确认不是该用例的业务结果；重启为单一 `node server.mjs` 服务进程后，DYN-07 重跑成功，后续用例继续完成。该事件不计入业务用例通过率，但应作为本地开发服务生命周期问题单独处理，不能作为 LLM 语义成功的证据。
